Verdict in one breath

"Unmodified" is dead on arrival, but not for the reasons the README feared. Bash, coreutils, herdr, treehouse (with --lease) and no-mistakes all already work here. What breaks is the seam between the MSYS world (bash hooks, watcher) and the Win32 world (claude.exe, herdr.exe): line endings at checkout, process identity, symlinks, and one path-shape check. All of it is surgical, and Kun already ships a windows-herdr-spike.yml CI lane measuring this same Git Bash + herdr path, so upstream is receptive.

PR-2 as shipped · the one non-trivial patch

One leaf library owns "what process is this and is it alive", so the callers stop spelling ps -o themselves. Non-MSYS branches are literally today's commands. The sketch's one-CIM-call-per-hop walk was measured at 22-24 s and replaced: MSYS /proc answers for the MSYS half of the chain for free, and one pwsh Get-Process/.Parent walk from the boundary winpid answers for the Win32 half in 0.83 s.

# bin/fm-proc-lib.sh (shipped)
case "$(uname -s 2>/dev/null)" in
  MINGW*|MSYS*|CYGWIN*) FM_PROC_OS=msys ;;
  *)                    FM_PROC_OS=posix ;;
esac
# capability, not platform, has the last word: a `ps` that
# accepts -o answers everything, so every ps-faking test
# in tests/ keeps working on Windows too
if [ "$FM_PROC_OS" = msys ] \
   && LC_ALL=C ps -o comm= -p $$ >/dev/null 2>&1
then
  FM_PROC_OS=posix
fi

# Segment 1: MSYS processes, straight from /proc. No fork.
# exename is what `ps -o comm=` prints, cmdline is the
# REAL argument vector, ppid is right between MSYS procs.
_fm_proc_msys_row() {  # <pid>
  # these files have NO trailing newline, so read sets the
  # variable and THEN reports EOF: judge by value, and
  # bracket each redirection so a race stays silent
  { read -r exe  < "/proc/$1/exename"; } 2>/dev/null
  { read -r ppid < "/proc/$1/ppid";    } 2>/dev/null
  args=$({ tr '\0\n\t' '   ' \
             < "/proc/$1/cmdline"; } 2>/dev/null)
  printf '%s\t%s\t%s\t%s\n' "$1" "$ppid" "$exe" "$args"
}

# Segment 2: from the boundary (the MSYS process reporting
# PPID 1) upward, in ONE pwsh process. .CommandLine is NOT
# read - it costs a hidden CIM query per process, 38 s for
# six hops - so a native ancestor reports its path as args.
_fm_proc_win_chain() {  # <win32 pid>
  FM_PROC_QUERY_PID=$1 pwsh -NoProfile -NonInteractive \
    -Command '
    $ErrorActionPreference = "SilentlyContinue"
    $p = Get-Process -Id ([int]$env:FM_PROC_QUERY_PID)
    for ($i = 0; $i -lt 16 -and $p; $i++) {
      $q = $null; try { $q = $p.Parent } catch {}
      $c = $p.ProcessName
      try { if ($p.Path) { $c = $p.Path } } catch {}
      "{0}`t{1}`t{2}" -f $p.Id, `
        $(if ($q) { $q.Id } else { 0 }), $c
      $p = $q
    }'
  # bash then strips CR, turns \ into /, and drops a
  # trailing .exe so basename and ^pi$ still match. Doing
  # that here rather than inside pwsh is what lets a Linux
  # test drive this branch.
}

fm_proc_comm() {  # <pid>
  if [ "$FM_PROC_OS" = msys ]; then
    _fm_proc_msys_field "$1" comm  # memo, /proc, or pwsh
  else
    ps -o comm= -p "$1" 2>/dev/null       # today's line
  fi
}

fm_pid_alive() {  # <pid>
  kill -0 "$1" 2>/dev/null && return 0
  [ "$FM_PROC_OS" = msys ] || return 1
  ps -W | awk -v p="$1" '$4==p{f=1} END{exit !f}'
}

Callers: fm-harness.sh detect_own, fm-session-lock-lib.sh fm_harness_pid_alive and its ancestry walk, fm-wake-lib.sh fm_pid_alive, fm-backend.sh cmux ancestry (Darwin-only, untouched). Each keeps its own per-hop loop and gains ONE line, fm_proc_chain_prime "$pid" before it: a caller's field reads happen inside $(...), and a subshell cannot write back, so the chain has to be memoised in the caller's own shell or the walk pays one pwsh process per hop. The MSYS ancestry necessarily yields the harness's WIN32 pid, so that is what fm-lock.sh records in state/.lock and what fm_pid_alive probes.

Why this is enough
  • Harness type already resolves through the CLAUDECODE=1 marker (layer 1), so only lock identity and liveness were blind.
  • Watcher and daemon are MSYS processes; their mutual kill -0, /proc, mkfifo, trap, and wait paths already work (verified /proc/$$/stat).
  • Cost (measured, not estimated): 0.9 s per ancestry walk - 0.06 s of /proc reads plus one 0.83 s pwsh start; the Stop hook fires once per turn, not per poll. The watcher's poll loop uses herdr agent get, not ps.
  • Test story: PR-2 ships tests/fm-proc-lib.test.sh that fakes uname and a pwsh stub emitting a canned chain, so Linux CI covers the MSYS branch too, mirroring how upstream fakes herdr in fm-backend-herdr.test.sh.
  • Rejected: wmic (removed in current Win11), tasklist (no parent id), a Go helper (new build artifact for one query).

Risks and open questions

what could still sink this
R1

Hook shell on Windows: retired. Measured in Phase A (finding 11): Claude Code runs project hooks in Git Bash with a forward-slash CLAUDE_PROJECT_DIR, and exec "$CLAUDE_PROJECT_DIR"/bin/… works unchanged.

R2

Upstream velocity. bin/ changes daily and PR-2 touches four hot files. Mitigation: a leaf library the callers source, so the diff in each hot file is one function swap; rebase before every push; open the issue before the PR so Kun can steer the shape.

R3

MSYS path conversion (finding 12). A single --match "/…" or a regex handed to herdr.exe can be rewritten to C:\… silently. Audit every fm_backend_herdr_cli argument in Phase A; if any is hit, scope MSYS2_ARG_CONV_EXCL to that call rather than globally.

R4

herdr Windows preview semantics. Kun's spike flagged foreground_process_group_id as possibly absent on Windows, which downgrades the focus-safe idle-shell proof. Nested bash-in-pwsh (D2) also changes what pane process-info sees. Both are measurable in the lab session before PR-4 is written.

R5

Containment. Crewmates run claude --dangerously-skip-permissions in worktrees; on this machine the only containment is git + worktrees until P8 imaging. Same posture as the dotfiles cc alias, just multiplied by the fleet size. Keep the fleet at one or two crewmates until P8.

R6

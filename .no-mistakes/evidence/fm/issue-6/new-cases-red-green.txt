-------------------------------------------------------------------

1. test_hook_claude_mode_window_is_a_wall_clock_deadline

                   of whatever the host charges: expected exit 2, got 0
   BRANCH ok - fm-turnend-guard --claude: the cooperation window is a wall-clock
               deadline, so a claim 8 s out misses a 3 s window

2. test_hook_claude_mode_recorded_claim_widens_the_window
   BASE   not ok - a home that measured 4000ms to claim must still be waiting 4 s
                   in, instead of forcing a continuation: expected exit 0, got 2
   BRANCH ok - fm-turnend-guard --claude: a recorded time-to-claim widens the
               window to twice it

3. test_hook_claude_mode_default_window_ignores_a_late_claim  (negative control)
   BASE   ok - fm-turnend-guard --claude: with no recorded time-to-claim the
               window is exactly FM_CLAUDE_AUTOARM_SYNC_WAIT_MS
   BRANCH ok - (same line)
   This one is the deliberate negative control and passes on both sides, which
   is what makes case 2 attributable to the record rather than to a guard that
   now waits for any late claim.

4. test_hook_claude_mode_caps_the_widened_window
   BASE   not ok - the default 15 s cap must still hold an 8 s claim inside the
                   window: expected exit 0, got 2
   BRANCH ok - fm-turnend-guard --claude: the cap bounds what a measurement may
               widen the window to

5. test_hook_claude_mode_malformed_cap_falls_back_to_the_default
   BASE   not ok - a malformed cap must fall back to the 15 s default, which
                   still holds an 8 s claim: expected exit 0, got 2
   BRANCH ok - fm-turnend-guard --claude: a malformed cap falls back to the
               default rather than to no window or an error

6. test_hook_claude_mode_malformed_claim_record_keeps_the_default_window
   BASE   not ok - a malformed time-to-claim record (not-a-number) must leave the
                   window at FM_CLAUDE_AUTOARM_SYNC_WAIT_MS: expected exit 2, got 0
   BRANCH ok - fm-turnend-guard --claude: a malformed time-to-claim record
               neither widens the window nor breaks the deadline

7. test_hook_claude_mode_leading_zero_claim_record_is_decimal
   BASE   not ok - a recorded 07000 must widen the window to twice its DECIMAL
                   value (14000 ms), not to twice octal 3584: expected exit 0, got 2
   BRANCH ok - fm-turnend-guard --claude: a leading-zero time-to-claim record is
